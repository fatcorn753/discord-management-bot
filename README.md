# 管理補助bot（Discord サーバー管理 Bot）

モデレーション・自動対策・ログ・入退室・ロール・チケット・投票/抽選・予約投稿に加え、
**荒らし対策の認証ゲート**と**チャンネル構成のバックアップ/復元**を備えた、日本語の統合型 Discord Bot です。
コマンドはすべて日本語で、ジャンルごとのグループにまとまっています。

---

## 主な機能とコマンド

`/` を押してグループ名（`/処罰` など）を入力すると、その中のコマンドが説明つきで一覧に出ます。
`/ヘルプ` では、**あなたが使える**コマンドだけを表示します。

| グループ | できること | 必要な権限 |
|---|---|---|
| `/キック` `/バン` `/バン解除` | メンバーの追放と解除。退出済みの人もID指定でBANできます | キック / BAN |
| `/処罰` | タイムアウト、警告（付与・一覧・削除・全消去）。警告が一定数で自動処罰 | メンバーをタイムアウト |
| `/自動対策` | 連投・招待リンク・全リンク・大量メンション・NGワード・大量参加（荒らし）の自動対応 | サーバー管理 |
| `/管理` | 一括削除・全消去・スローモード・ロック・お知らせ・代理発言 | 一括削除/お知らせ/代理発言=メッセージの管理、全消去/スローモード/ロック=チャンネルの管理 |
| `/認証` | ボタン式の認証ゲート。認証するまでサーバーを見せない | サーバー管理 |
| `/入退室` | 参加・退出メッセージ、参加時の自動ロール | サーバー管理 |
| `/ロール` | ロールの付与/剥奪、リアクションロール | ロールの管理 |
| `/チケット` | ボタン式のサポート窓口。クローズ時に会話の記録を保存 | 設置・設定=サーバー管理 / クローズ=作成者かスタッフ |
| `/予約投稿` | 日時を指定して自動投稿 | メッセージの管理 |
| `/バックアップ` | チャンネル・カテゴリー構成の保存と、無いものだけの復元 | 管理者 |
| `/イベント` | 投票（誰でも）、抽選（サーバー管理） | 抽選はサーバー管理 |
| `/情報` | ユーザー・サーバー・ロール・アバター・応答速度 | なし |
| `/設定` | 導入チェック（診断）、ログ送信先、警告しきい値 | サーバー管理 |

> 権限の足りない人が実行すると、必要な権限を示す拒否メッセージが出ます（表示の制限だけに頼らず、実行時にも検査します）。

## 使うだけの人へ（Bot を運営者から招待してもらう場合）
Bot を動かしているのが別の人なら、**招待されたあとの作業だけ**で使えます。
1. 運営者から受け取った招待 URL でサーバーに招待します（「サーバー管理」権限が必要）。
2. 下の「6. 招待したらすぐやること」を実施します。
3. `/設定 診断` で、権限・ロール順位・ログ送信先をチェックします。

Bot を**自分で動かす**場合は、続きの「導入手順」に進んでください。

## 導入手順（Bot を自分で動かす人向け）

### 1. 準備するもの
- Python 3.9 以上
- 常時動かせる環境（自分のPC、Ubuntu などのサーバー）。**Bot が動いている間だけ**コマンドと自動対策が働きます

### 2. Discord 側の準備（Developer Portal）
1. [Discord Developer Portal](https://discord.com/developers/applications) にログインし、**「新しいアプリケーション」**を押して名前（例: 管理補助bot）を付けます。
2. 左メニューの **「Bot」** を開きます。
3. **「特権ゲートウェイインテント」**で、次の2つを**オン**にして保存します。
   - 「サーバーメンバーインテント」（入退室・メンバー情報）
   - 「メッセージ内容インテント」（自動対策でメッセージを読むため）
4. **「トークンをリセット」**を押し、表示されたトークンをコピーします。**一度しか表示されません。パスワードと同じなので、他人に見せないでください。**

### 3. インストールと設定
**macOS / Linux**
```bash
cd discord-management-bot
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp config.example.json config.json
```
**Windows（PowerShell）**
```powershell
cd discord-management-bot
py -m venv .venv
.venv\Scripts\pip install -r requirements.txt
copy config.example.json config.json
```
以降の `.venv/bin/python` は、Windows では `.venv\Scripts\python` に読み替えてください。
`config.json` を編集して、`token` に貼り付けます。

| 項目 | 説明 |
|---|---|
| `token` | Bot トークン（必須） |
| `status` | Bot のステータス表示 |
| `test_guild_id` | 開発用。サーバーIDを入れると、そのサーバーだけにコマンドが**即時反映**されます。**本番や一般公開では必ず `null`**。設定中は他のサーバーでコマンドが出ず、さらに**別の場所の Bot がグローバルに登録したコマンドと重複して、同じコマンドが2つ表示されます** |
| `utc_offset_hours` | 予約投稿の日時入力の時差。日本は `9` |
| `require_approval` | `true` にすると、**承認制**になります（下の「サーバーの承認」）。省略・`false` は従来どおり（どのサーバーでも使える） |
| `owner_ids` | Bot の持ち主のユーザーID（配列）。承認の DM が届き、承認の操作ができる人 |
| `allowed_guild_ids` | あらかじめ許可しておくサーバーIDの配列。承認制のときは、すでに使っているサーバーをここに入れておく |
| `support_url` `privacy_url` `terms_url` | 任意。設定すると `/ヘルプ` にリンクが表示されます |

### 4. 起動
```bash
.venv/bin/python main.py
```
`✓ ロード: …` と `ログイン: 管理補助bot…` が表示されれば成功です。
トークンの間違いやインテント未許可のときは、原因と対処が日本語で表示されます。

### 5. サーバーへ招待
次の URL の `CLIENT_ID` を、Developer Portal の「一般情報」にある**アプリケーションID**に置き換えて開き、サーバーを選びます（URL を開く人には、そのサーバーの「サーバー管理」権限が必要です）。

```
https://discord.com/oauth2/authorize?client_id=CLIENT_ID&scope=bot+applications.commands&permissions=1099780189270
```

- 上の権限値は、この Bot の全機能に必要な最小限です（チャンネルを見る・メッセージ送信・埋め込み・ファイル添付・履歴・リアクション・メッセージ/チャンネル/ロールの管理・キック・BAN・タイムアウト）。
- 管理者権限で簡単に済ませたい場合は `permissions=8` にします。
- **他の人にも招待してもらう（公開 Bot にする）場合**: Developer Portal の「Bot」で「Public Bot」をオンにします。参加サーバー数が増えると、Discord が特権インテント（メンバー・メッセージ内容）の申請や認証を求めることがあります。条件は変わることがあるため、Discord の最新の案内を確認してください。公開前に、`PRIVACY.md` `TERMS.md` を自分の情報で記入し、`config.json` の `support_url` などを設定してください。

### サーバーの承認（友達のサーバーだけで使う）
`config.json` に `"require_approval": true` と、自分のユーザーIDを入れた `"owner_ids": [あなたのID]` を設定すると、**Bot が新しいサーバーに追加されたとき、持ち主に DM で通知が届きます**。

1. 友達が招待 URL から Bot を追加します。
2. 持ち主に DM が届きます（サーバー名・ID・持ち主・メンバー数つき）。ボタンは **【許可する】** と **【断って退出させる】** です。
3. **許可するまで、そのサーバーでは Bot の機能がすべて止まります。** コマンドだけでなく、メッセージの監視（自動対策・ログ）、入退室メッセージ、リアクションロールなども動きません。
4. 許可すると、再起動なしですぐ使えます。断ると、Bot はそのサーバーから退出します。

- すでに使っているサーバーは、承認制にする前に `allowed_guild_ids` に入れてください（入れないと、再起動後に承認待ちになります）。
- `/運営 サーバー一覧` `サーバー許可` `サーバー取消` で、あとから許可の確認・追加・取り消しができます（持ち主だけ。**Bot とのDMでだけ**使えて、サーバーのコマンド候補には出ません）。
- 持ち主は、承認待ちのサーバーの中でもコマンドを使えます（承認の操作のため）。

### 6. 招待したらすぐやること（ここが一番つまずきやすい）
1. **Bot のロールを上へ動かす**: サーバー設定 →「ロール」で、`管理補助bot` のロールを、認証ロールや付与したいロールより**上**にドラッグします。Bot は自分より下のロールしか付与・処罰できません。
2. **`/設定 診断`** を実行します。権限・ロール順位・ログ送信先を一括でチェックし、直すべき点を示します。
3. **ログの送信先を決めます**（未設定だと記録が残りません）:
   ```
   /設定 ログ チャンネル:#ログ
   /設定 モデログ チャンネル:#モデログ
   /設定 自動対策ログ チャンネル:#自動対策ログ
   ```
4. 自動対策を使うなら **`/自動対策 全体 有効:True`** を忘れずに（これがOFFだと個別設定は動きません）。

## 機能の使い方

### 🔐 認証ゲート（荒らし対策）
```
/認証 設置 チャンネル:#認証 ロール:@認証済み 最低日数:7 連絡先:#サポート
```
参加者が「✅ 認証する」ボタンを押すとロールが付き、サーバーが見えるようになります。
仕上げに、`@everyone` の権限で**認証チャンネル以外を非表示**にし、認証ロールに閲覧権限を与えてください。
アカウントが新しすぎる人には、**何日以降にもう一度試せるか**と連絡先が表示されます。`/認証 状況` で設定を確認できます。
（参加時に無条件でロールを付ける `/入退室 自動ロール` は、認証ゲートと併用しないでください。）

### 🤖 自動対策
`/自動対策 全体` をONにしてから、`招待リンク` `全リンク` `メンション` `連投` `大量参加` `ワード追加` を設定します。
自動で削除・タイムアウト・キックされた人には、理由と「誤りの場合の連絡先」が伝わります。`/自動対策 状況` で現在の設定を確認できます。

- **対象外の人**: 管理者・メッセージの管理・サーバー管理の権限を持つ人と Bot は、自動対策の対象になりません。**管理者のアカウントでテストしても何も起きません**（テスト用の別アカウントで確認してください）。
- **NGワードは部分一致**です（大文字小文字は区別しません）。短い語は、別の単語に含まれて誤検知することがあります。
- メッセージを**編集して**NGワードやリンクにしても、編集後に再検査されます。
- チャンネル別・ロール別の除外設定はありません。

### 🧹 メッセージの削除
- `/管理 一括削除 件数:50` — 13日以内のメッセージを新しい順に最大1000件。20件以上は確認ボタンが出ます。
- `/管理 全消去` — チャンネルを**複製して元を削除**します。古い投稿も消せますが、元には戻せません（確認あり）。

### 🕒 予約投稿
```
/予約投稿 追加 日時:18:30 チャンネル:#お知らせ 本文:今夜20時からイベントです\n参加してね
/予約投稿 追加 日時:2026-10-25 18:30 チャンネル:#お知らせ 本文:本文 埋め込み:True タイトル:イベント告知
```
- 日時の書き方（日本時間）: `30m` `2h` `1d`（今から）、`18:30`（今日。過ぎていれば明日）、`10-25 18:30`、`2026-10-25 18:30`。
- 30秒後〜1年後、未投稿は25件まで。再起動しても予約は残ります。停止中に時刻を過ぎた予約は、1時間以内なら起動後に投稿し、それ以上は投稿せずモデログに通知します。
- `@everyone` やロールへのメンションは、予約した本人にその権限がある場合のみ有効です。

### 📦 バックアップ / 復元
```
/バックアップ 保存 名前:通常運用
/バックアップ 復元 名前:通常運用
```
- 保存するもの: カテゴリー／チャンネルの名前・種類・順序・トピック・スローモード・年齢制限・ボイス設定、**ロール単位**の権限上書き。
- 保存しないもの: メッセージ、ロール自体、メンバー個人への権限上書き、スレッド。
- 復元は**追加のみ**: 既存のものは変更も削除もしません。ロールは名前で対応づけ、無いロールの上書きは省略します（先にロールを作り直してください）。削除したチャンネルの**メッセージは戻りません**。

### 🎫 チケット
`/チケット パネル` で設置し、`/チケット 設定` でスタッフロール・ログチャンネルを設定します。
クローズは、作成者かスタッフがボタン（または `/チケット クローズ`）で行います。確認を挟み、**会話の記録（テキスト）をログチャンネルに送ってから**チャンネルを削除します。**記録を送れなかった場合は、チャンネルを削除せずに中止します**（ログチャンネルが未設定だと記録は残りません）。チケット内の案内にも「記録される」旨を表示します。

### 🎉 抽選・投票
`/イベント 抽選 賞品:… 期間:1h` で開催します。終了すると元のメッセージが「終了」表示に変わり、当選者が発表されます。
`/イベント 抽選終了` で今すぐ締め切り、`/イベント 再抽選` で前回の当選者を除いてやり直せます。
投票はリアクション式の簡易版です（締め切り・集計表示はありません）。

## 保存するデータとプライバシー

この Bot は `data/bot.db`（SQLite）に次を保存します。

| データ | 内容 |
|---|---|
| サーバー設定 | ログ送信先・各機能の設定（チャンネル/ロールのID、NGワードなど） |
| 警告 | 対象と実行者のユーザーID、理由、日時 |
| チケット | チャンネルID、作成者のユーザーID |
| リアクションロール | メッセージID・絵文字・ロールID |
| 抽選 | 賞品名、参加者のユーザーID（終了後30日で削除） |
| 予約投稿 | 投稿予定の本文・宛先・予約者のID（投稿後に削除） |
| 予約投稿 | 投稿内容・宛先・日時（投稿後に削除） |
| バックアップ | チャンネル構成（メッセージは含みません） |

- **ログ機能**は、設定したログチャンネルに、メッセージの**編集前後・削除された本文**、入退室、ロール変更などを書き込みます。使う運営者は、メンバーにその旨を周知してください。
- チケットの会話の記録は、設定したログチャンネルにだけ送られます。
- **Bot がサーバーから外れる（退出・キックされる）と、そのサーバーのデータは 30 日後に削除されます。** 30 日以内に再招待すれば、設定はそのまま使えます。すぐ消したい場合は、提供者に連絡してください。
- 公開運用では、[PRIVACY.md](PRIVACY.md)（プライバシー）と [TERMS.md](TERMS.md)（利用規約）の**ひな形**を編集して公開し、`config.json` の `privacy_url` / `terms_url` / `support_url` に設定してください。

## 運用

### 常時稼働（Linux / systemd の例）
`/etc/systemd/system/kanri-bot.service`:
```ini
[Unit]
Description=管理補助bot
After=network-online.target

[Service]
User=botuser
WorkingDirectory=/opt/discord-management-bot
ExecStart=/opt/discord-management-bot/.venv/bin/python -u main.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```
```bash
sudo systemctl daemon-reload && sudo systemctl enable --now kanri-bot
journalctl -u kanri-bot -f      # ログを見る
```
**同じトークンで2か所から起動しないでください**（コマンドに二重で返信します）。

### バックアップと更新
- **データのバックアップ**: Bot を止めてから `data/` フォルダをコピーします（`bot.db` と `bot.db-wal` `bot.db-shm` を一緒に）。
- **更新**: Bot を止め、新しいファイルに置き換えて `pip install -r requirements.txt` を再実行し、起動し直します。`data/` と `config.json` はそのまま使えます。
- 起動時にコマンドを同期するため、コマンド名が変わる更新のあとは、反映に最大1時間かかることがあります（`test_guild_id` 設定時は即時）。

### トークンを漏らしてしまったら
Developer Portal の「Bot」→「トークンをリセット」で**すぐ再発行**し、`config.json` を差し替えてください。`config.json` と `data/` は `.gitignore` 済みです。コミットしないでください。
